# Проверка перед защитой

## Автоматические проверки

Выполнить `npm run check` и `npm test` из корня проекта.

## Ручная проверка в VS Code

1. F5 → открыть `examples/algorithms.cjs` в новом окне.
2. Запустить команду; указать `uniqueSlow, uniqueFast` и `100, 1000, 5000, 10000`.
3. Выбрать случайный массив. Проверить две линии и 8 строк таблицы.
4. Переключить логарифмическую шкалу n, навести курсор на точку.
5. Сохранить JSON и CSV. Сверить медиану в таблице и экспорте.
6. Повторить с одной функцией и одним размером: график должен показать одну точку.
7. Для `examples/custom-input.mjs` выбрать `linearSearch, binarySearch`
   и генератор «Свой генератор».
8. Ввести отсутствующее имя экспорта: должно появиться понятное сообщение об ошибке.
9. Ввести размеры `100, abc`: запуск должен быть отклонён.
10. Запустить тяжёлый эксперимент и нажать отмену в уведомлении.
11. Для бесконечного цикла из `test/fixtures/hangs.cjs` указать `hang`
    и тайм-аут 1 с. Редактор должен остаться отзывчивым.

Автоматические тесты не заменяют проверку интерфейса в Extension Development Host.

## Выполненная проверка версии 0.1.0

- Проверка синтаксиса и 12 автоматических сценариев прошли на Node.js 24.22.1 / Linux.
- Реальный VS Code 1.144.0 обнаружил и активировал расширение; команда и настройки
  зарегистрированы (Extension Host test).
- В браузере проверен отчёт на фактических измерениях двух функций, включая
  переключение логарифмической шкалы.
- VSIX собран официальным упаковщиком `@vscode/vsce`.

Полный ручной проход диалогов команды и экспорта в VS Code остаётся сценарием
проверки при установке; автоматический Extension Host test проверяет загрузку
и регистрацию расширения, а не клики по диалогам.
