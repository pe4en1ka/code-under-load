# Проверка перед защитой

## Автоматические проверки

Выполнить `npm run check` и `npm test` из корня проекта.

## Ручная проверка в VS Code

1. F5 → открыть `examples/algorithms.cjs` в новом окне.
2. Запустить команду; указать `uniqueSlow, uniqueFast` и `100, 1000, 5000, 10000`.
3. Выбрать случайный массив. Проверить две линии и 8 строк таблицы.
4. Переключить логарифмическую шкалу n, навести курсор на точку.
5. Сохранить JSON и CSV. Сверить медиану в таблице и экспорте.
6. Повторить с одной функцией и одним размером: график должен показать одну точку.
7. Для `examples/custom-input.mjs` выбрать `linearSearch, binarySearch`
   и генератор «Свой генератор».
8. Ввести отсутствующее имя экспорта: должно появиться понятное сообщение об ошибке.
9. Ввести размеры `100, abc`: запуск должен быть отклонён.
10. Запустить тяжёлый эксперимент и нажать отмену в уведомлении.
11. Для бесконечного цикла из `test/fixtures/hangs.cjs` указать `hang`
    и тайм-аут 1 с. Редактор должен остаться отзывчивым.

Автоматические тесты не заменяют проверку интерфейса в Extension Development Host.

## Статический анализ и f(n) (0.7.0)

complexity.test.js проверяет последовательные и вложенные циклы,
логарифмический шаг, сортировку, вызов бинарного поиска в цикле, память
массивов, разные размерности входа, примеры C++/JavaScript/Python,
неопределённые вызовы и рекурсию. Отдельно проверяются прямые значения
математических функций, диапазоны, обе шкалы, отсутствие нечисловых
координат, экранирование HTML и сохранение графика времени.

Для ручной проверки: вызовите «Оценить сложность по исходнику» на
программе с циклом и бинарным поиском; ожидается O(n log n) и O(n) памяти.
Проверьте ссылки на строки и условия. Программа запускаться не должна.
Затем выполните обычный бенчмарк: график миллисекунд должен сохраниться.
На графике f(n) включите n³ и n!, меняйте максимальное n, отключайте
функции и переключайте шкалу f(n). Никакой подгонки к замерам нет.


## Фиксированная шкала f(n) (0.7.1)

Вертикальная шкала математического графика больше не зависит от выбранных
функций и диапазона n. Линейная шкала: 0–1000, шаг 200. За общий ориентир
взято n³ при n=10; шаг рассчитан на пять удобных интервалов. Логарифмическая
шкала фиксирована от 1 до 1000, с делениями 1, 10, 100, 1000. При пустом
выборе оси сохраняются. Кривые обрезаются границей области построения;
большие значения не сплющиваются в горизонтальную линию и не увеличивают
масштаб. Тест проверяет неизменность делений для всех функций, крайних
размеров, пустого выбора и обеих шкал, а также координаты обрезанных кривых.
График замеров времени этим изменением не затронут.


## Одинаковые шкалы n и f(n) (0.7.2)

В линейном режиме обе оси имеют одинаковые диапазон, шаг и длину
единичного отрезка. При изменении N диапазоны меняются вместе;
выбор функций на шкалы не влияет. Например, при N=10 обе оси
идут от 0 до 10 с шагом 2, при N=100 — от 0 до 100 с шагом 20.
Диапазон округляется вверх до удобного деления. Область построения
квадратная, поэтому f(n)=n проходит под 45°. Кривые, выходящие за
диапазон, обрезаются. В дополнительном логарифмическом режиме f(n)
преобразуется логарифмом; равенство единиц для этого режима не заявляется.
Тесты проверяют равенство делений, синхронное изменение с N и наклон
линейной функции, включая некруглые N.


## Ввод и вывод программы (0.7.3)

В режиме main каждый раскрывающийся блок теста содержит stdin, stdout
и stderr, если он непустой. Сохраняется именно подготовленный вход,
переданный процессу: из файла или генератора. Для stdin показывается
начало до 8000 Unicode-символов и полный размер в байтах; усечение явно
подписано. Формирование превью выполняется до измеряемых запусков.
Декодирование ограничено первыми 32000 байтами и сохраняет целые UTF-8
символы. Отчёт экранирует все три потока. JSON сохраняет stdinPreview
и stdinTruncated. Старый результат без stdin отличается от пустого ввода.

Проверки: реальные файловые и сгенерированные входы, payload прогресса,
пустой и большой stdin, многобайтные символы и emoji на границе,
HTML-экранирование и порядок stdin → stdout → stderr.
