# Архитектура расширения

VS Code загружает расширения в Extension Host. Манифест `package.json`
объявляет команду, контекстное меню и параметры настроек. При вызове команды
VS Code активирует расширение через `activate(context)` в `src/extension.js`.
Регистрация команды и панели добавляется в `context.subscriptions` для освобождения.

Поток данных:

```text
Команда VS Code → ввод параметров → validateConfig
  → runner.js → отдельный Node.js / worker.cjs
  → импорт пользовательского модуля
  → benchmark.js: генерация → прогрев → замеры → статистика
  → IPC: прогресс и результат
  → report.js → Webview: SVG-графики и таблица
  → сообщение export → диалог сохранения → JSON / CSV
```

- `configuration.js` преобразует ввод пользователя и объединяет его с настройками.
- `benchmark.js` не зависит от VS Code: это отдельно проверяемое ядро измерений.
- `runner.js` запускает Node.js без командной оболочки, обрабатывает IPC,
  ошибки запуска, аварийный выход, тайм-аут и AbortSignal.
- `worker.cjs` принимает один эксперимент и возвращает результат.
- `report.js` формирует HTML и SVG. Пользовательские строки экранируются.
- `media/report.js` переключает шкалу и передаёт запрос на экспорт в расширение.
- `export.js` формирует CSV; JSON сохраняет конфигурацию и все исходные измерения.

Webview получает доступ только к каталогу `media`, использует Content Security
Policy и nonce для скрипта. Обработчик сообщений принимает только два формата
экспорта, а путь выбирается через системный диалог VS Code.
Запуск отключён в недоверенных рабочих папках.

Расширение не изменяет исследуемый исходный код. Node.js исполняет сохранённый
модуль, поэтому выбранные функции должны быть экспортированы и совместимы с Node.js.
Полный текст функции не извлекается из выделения: это сохраняет её импорты и окружение.

## Поддержка Python и C++ в версии 0.2.0

`languages.js` определяет язык по расширению, `validation.js` проверяет общий
контракт. `runner.js` выбирает JavaScript, Python или C++. Настройки путей
интерпретаторов и компилятора задаются отдельно.

Python запускается через `workers/python_worker.py`: импорт через importlib,
таймер perf_counter_ns, поддержка awaitable и генератора generate_input.
C++ запускается через `cpp-runner.js`: создаётся временная обёртка на основе
`workers/cpp_harness.cpp`, файл компилируется и выполняется. Используются
std::chrono::steady_clock, std::apply для кортежей аргументов и барьер компилятора.

`process.js` управляет внешним процессом и его деревом. `external-runner.js`
разбирает протокол JSON с маркером, проверяет точки и рассчитывает статистику
тем же модулем, что и JavaScript. Поэтому webview и экспорт едины для всех языков.
Компиляция и генерация данных находятся вне измеряемого интервала.

## Подключение C++ файлов с main

Перед включением пользовательского файла обёртка сохраняет состояние макроса main,
переименовывает этот идентификатор в code_under_load_user_main и затем восстанавливает
состояние макроса. Поэтому собственная точка входа измерительной программы не
конфликтует с пользовательской. Файл на диске не переписывается, пользовательский
main не вызывается. Измеряемая функция по-прежнему выбирается по имени.

## Режим программы целиком

В режиме program модуль program-runner.js компилирует исходный C++ напрямую,
без обёртки и переименования main. Для каждой точки читается выбранный входной
файл, затем на каждый повтор создаётся новый процесс. process.js подаёт байты
в stdin, закрывает поток, собирает stdout/stderr и возвращает время от запуска
процесса до закрытия его потоков. Компиляция и чтение входных файлов в измерение
не входят. Обработчик отчёта явно отличает это время от замера отдельной функции.
