# Код под нагрузкой

Расширение VS Code для исследования производительности функций **JavaScript,
Python и C++**. Запускает от одной до четырёх реализаций одного языка на данных
разного объёма и показывает график времени выполнения прямо в редакторе.

**Автор:** Мамедов Тимур Назимович, **группа М3108**.  
Лабораторная работа №3 по ИСРПО.

## Возможности

- Автоматическое определение языка по файлу: `.js`, `.cjs`, `.mjs`, `.py`, `.cpp`, `.cc`, `.cxx`.
- Сравнение до четырёх функций одного файла на общем графике.
- Встроенные случайные, возрастающие и убывающие массивы целых чисел.
- Пользовательские генераторы нескольких аргументов для всех трёх языков.
- JavaScript Promise и Python async; функции C++ с результатом или `void`.
- Прогрев, повторы, медиана, минимум, максимум, P95 и исходные замеры.
- Линейная или логарифмическая шкала размера входа, таблица, экспорт JSON/CSV.
- Отдельные процессы, общий тайм-аут и отмена из уведомления VS Code.
- Компиляция C++17 с `-O2` во временной папке, исключённая из замеров.
- Сохранение предыдущих параметров отдельно для каждого языка.

## Требования

VS Code 1.85+ и доверенная рабочая папка. Для каждого языка требуется только
соответствующий инструмент:

| Язык | Инструмент | Настройка пути |
|---|---|---|
| JavaScript | Node.js 18+ | `codeUnderLoad.nodePath` |
| Python | Python 3.9+ | `codeUnderLoad.pythonPath` |
| C++ | GCC `g++` или Clang `clang++`, C++17 | `codeUnderLoad.cppCompilerPath` |

Для Python и C++ отдельно устанавливать Node.js не нужно: расширение использует
Extension Host VS Code для управления процессами. Укажите полный путь к инструменту,
если он недоступен в PATH. При выборе Python укажите исполняемый файл интерпретатора,
в том числе из виртуального окружения, без дополнительных аргументов.
В Windows по умолчанию вызывается `python`, в Linux/macOS — `python3`.
Для C++ в Windows подходит GCC из MSYS2 UCRT64, для macOS — Clang из Command Line Tools.
MSVC `cl.exe`, CMake-проекты и дополнительные флаги линковки в этой версии не поддерживаются.

## Запуск

1. Откройте сохранённый файл поддерживаемого языка в VS Code.
2. Через `Ctrl+Shift+P` или контекстное меню вызовите
   **«Код под нагрузкой: Исследовать производительность»**.
3. Введите имена функций через запятую, затем возрастающие размеры входа.
4. Выберите встроенный массив или свой генератор аргументов.
5. Дождитесь отчёта. Для C++ сначала отображается этап компиляции.

Для C++ после открытия команды сначала выберите **«Отдельные функции»**
или **«Программа целиком через main»**. В режиме main имена функций вводить не нужно.
После запуска переключите шкалу, наведите курсор на точки или сохраните JSON/CSV.

Имя выделенной функции предзаполняется. В неподдерживаемом или пустом редакторе
открывается выбор файла. Модуль перед запуском сохраняется на диск.

### Готовые примеры

| Файл | Имена функций | Генератор |
|---|---|---|
| `examples/algorithms.cjs` | `uniqueSlow, uniqueFast` | Случайный массив |
| `examples/algorithms.py` | `unique_slow, unique_fast` | Случайный массив |
| `examples/algorithms.cpp` | `unique_slow, unique_fast` | Случайный массив |
| `examples/with_main.cpp` | `sum_values` | Случайный массив |
| `examples/custom-input.mjs` | `linearSearch, binarySearch` | Свой генератор |
| `examples/custom_input.py` | `linear_search, binary_search` | Свой генератор |
| `examples/custom_input.cpp` | `linear_search, binary_search` | Свой генератор |

Начните с размеров `100, 1000, 5000`. Для квадратичных алгоритмов увеличение до
миллиона элементов может превысить тайм-аут; при необходимости отмените запуск.

## Контракт функций

Измеряются именованные функции сохранённого файла, а не произвольный фрагмент кода.
Все сравниваемые функции должны принимать одинаковую структуру аргументов.
Со встроенным генератором передаётся один массив или список целых чисел;
для C++ это `std::vector<int>`.

### JavaScript

Экспортируйте функции через CommonJS или ESM:

```js
function unique(values) { return [...new Set(values)]; }
module.exports = { unique };
```

Для default-экспорта введите `default`. Пользовательский генератор
`generateInput(size, seed)` возвращает массив аргументов. Поддерживаются Promise.
Импорты и зависимости должны разрешаться обычным Node.js; браузерного DOM нет.

### Python

Определите функции на верхнем уровне модуля:

```python
def unique(values):
    return list(dict.fromkeys(values))
```

Для своих аргументов определите `generate_input(size, seed)`, возвращающий список
или кортеж аргументов. Например, `return [list(range(size)), size - 1]` передаёт
в функцию два аргумента. Асинхронные функции и генераторы аргументов поддерживаются.
Соседние модули можно импортировать обычным `import`; пакетные относительные импорты
в самостоятельном `.py`-файле требуют соответствующего Python-окружения/обёртки.
Код под `if __name__ == '__main__':` не выполняется при импорте.

### C++

Выберите самостоятельный исходный файл с исследуемыми функциями. **Наличие `main` допускается**:

```cpp
#include <vector>
long long sum(const std::vector<int>& values) {
    long long result = 0;
    for (int value : values) result += value;
    return result;
}
```

При включении исходника в измерительную обёртку препроцессор временно переименовывает
пользовательский `main` в `code_under_load_user_main`. Исходный файл не изменяется;
в режиме отдельных функций пользовательский `main` не вызывается. Работают `main()` и
`main(int, char**)`. Глобальные и статические инициализаторы по-прежнему выполняются
при запуске процесса, вне замеров функций.

В режиме отдельных функций в поле имён указывайте исследуемую функцию, например `sum` или
`load_test::benchmark_main`, а не `main`. Встроенный генератор передаёт один
`std::vector<int>`; простого переименования `main` в `run_main` недостаточно,
если такая функция не принимает аргументов. Для функции без аргументов можно
использовать свой генератор, возвращающий `std::tuple<>`.

Допустимы параметры по значению, `const&` и `&`, возвращаемое значение или `void`.
Функции в пространствах имён указываются как `algo::sort`. Для нескольких аргументов
определите `generate_input(std::size_t size, std::uint32_t seed)`, возвращающий
`std::tuple` аргументов. Пример — `examples/custom_input.cpp`.

Выбранный файл включается в создаваемую обёртку и компилируется с `-std=c++17 -O2`.
Локальные заголовки подключаются из исходного расположения. Сторонние библиотеки,
дополнительные единицы трансляции, конфигурации CMake и специальные флаги сборки
автоматически не подхватываются. Результат вызова передаётся через барьер компилятора,
чтобы неиспользуемое возвращаемое значение не позволило удалить вычисления.
Компилятор и временный исполняемый файл запускаются без командной оболочки;
после завершения или отмены временная папка удаляется.

## Программа C++ целиком через main

Этот режим предназначен для обычных программ, которые читают вход из `std::cin`
и печатают ответ в `std::cout`. Изменять исходный `.cpp` и добавлять обёртку не нужно.

1. Откройте обычный `.cpp` с `main` и вызовите команду расширения.
2. Выберите **«Программа целиком через main»**.
3. Выберите **«Генератор входных данных»**.
4. Укажите размеры, например `100, 1000, 5000, 10000`, и генератор:
   случайный (seed = 42), возрастающий или убывающий массив — те же значения,
   что в режиме функций.
5. Выберите формат stdin, который читает программа:
   - **n и массив**: первая строка — n, вторая — n чисел через пробел;
   - **Только массив**: n чисел через пробел;
   - **Только n**: одна строка с размером задачи.
6. Дождитесь графика; блок **«Вывод программы»** содержит stdout последнего повтора.

Например, откройте `examples/program_sum.cpp`, выберите генератор «Возрастающий
массив», размеры `10, 100, 1000` и формат «n и массив». Ответы: `45`, `4950`, `499500`.
Данные генерируются до замера; каждый повтор получает одинаковый stdin.

**Готовые файлы тоже поддерживаются.** На шаге 3 выберите «Готовые входные файлы»,
затем `.in` / `.txt` / `.dat` и укажите n для каждого файла в показанном порядке.
Примеры: `examples/program-inputs/input-10.in`, `input-100.in`, `input-1000.in`.
В этом варианте n служит меткой графика, а байты файлов передаются без изменений.

Формат должен соответствовать программе. Для программы с командами, строками,
графами или иным протоколом подготовьте соответствующие входные файлы:
встроенный числовой генератор не угадывает произвольный формат stdin.
Собственный `generate_input` для аргументов функций по-прежнему доступен в режиме
«Отдельные функции»; он не преобразуется автоматически в текстовый ввод main.

Программа компилируется обычным способом с `-std=c++17 -O2`. Для каждого прогрева
и замера запускается **новый процесс**. Поддерживаются стандартные сигнатуры main,
включая argc/argv; дополнительных аргументов командной строки не передаётся.
Рабочая папка — папка исходника. Интерактивный ввод не поддерживается: после
сгенерированных данных или входного файла stdin закрывается, программа получает EOF.

В отличие от режима функций, здесь измеряется **полное время процесса**, включая
его запуск, main, ввод-вывод и завершение. Генерация данных, чтение файла самим расширением и компиляция
не учитываются. Прогревочные запуски могут прогреть файловый кэш, но каждый следующий
процесс начинает работу заново. Поэтому результаты двух режимов нельзя напрямую
сравнивать как время одной функции.

Общий тайм-аут включает компиляцию и все запуски. Ненулевой код завершения или
отмена останавливает эксперимент. Разрешены 1–20 входных файлов до 64 МиБ каждый;
для графика указываются возрастающие n в пределах общего ограничения размеров.
В JSON сохраняются имена и пути входных файлов, их размеры, исходные замеры и
конец stdout/stderr последнего измеренного запуска (до 8000 символов каждого).
Содержимое stdin в отчёт не копируется. В CSV добавлены имя входного файла и его
размер в байтах. Плагин не сверяет ответ с эталоном.

## Настройки

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `codeUnderLoad.nodePath` | `node` | Исполняемый файл Node.js |
| `codeUnderLoad.pythonPath` | пусто | Python; пусто означает системное имя для ОС |
| `codeUnderLoad.cppCompilerPath` | `g++` | GCC или Clang с GNU-интерфейсом |
| `codeUnderLoad.repetitions` | 7 | Измерений на точку, 3–50 |
| `codeUnderLoad.warmup` | 2 | Прогревочных вызовов на размер, 0–10 |
| `codeUnderLoad.timeoutSeconds` | 30 | Лимит всего эксперимента, 1–120 с |

Размеры — до 20 возрастающих целых чисел от 1 до 1 000 000. Общий тайм-аут
включает запуск интерпретатора, компиляцию C++, подготовку входа и все вызовы.
При этом в результатах учитывается только вызов функции и ожидание его завершения.

## Методика и ограничения

Перед каждым вызовом создаются свежие аргументы вне измеряемого интервала.
Встроенные генераторы используют одинаковый алгоритм и seed 42 во всех языках;
порядок функций чередуется между раундами. Пользовательский генератор должен
сам обеспечивать свежесть и воспроизводимость данных.

Медиана уменьшает влияние единичных выбросов. P95 вычисляется методом ближайшего
ранга и при семи повторах совпадает с максимумом. JSON сохраняет все исходные замеры.
На время влияют JIT, сборка мусора, выделение памяти, оптимизации и нагрузка ОС.
Для очень быстрых функций заметна погрешность таймера и вызова обёртки.
График не доказывает асимптотическую сложность и не проверяет правильность результата.

Один эксперимент сравнивает функции **одного языка и одного файла**. Прямое
сравнение языков в одном запуске в версии 0.4.0 не реализовано. Состояние
исследуемого модуля сохраняется между вызовами.

Код выполняется с обычными правами пользователя; отдельный процесс не является
песочницей. Обычный вывод Python и C++ отделён от протокола измерений. Тайм-аут
и отмена завершают процесс запуска; для Python/C++ завершается и его дерево процессов
(POSIX-группа или Windows taskkill). Самостоятельно отсоединённые фоновые процессы
не гарантированно управляются плагином. Исходники и результаты не отправляются в сеть.

## Установка и разработка

Установите `code-under-load-0.4.0.vsix` через **Extensions → … → Install from VSIX…**.
Для запуска из исходников откройте эту папку и нажмите **F5** с конфигурацией
«Код под нагрузкой». Примеры открывайте в новом окне Extension Development Host.

Для разработки и автоматических тестов нужен Node.js, Python и GCC/Clang:

```sh
npm run check
npm test
```

Зависимости для работы расширения и тестов устанавливать не нужно.
Единственная dev-зависимость — официальный упаковщик `@vscode/vsce`.
Для сборки VSIX используйте Node.js 20+:

```sh
npm install
npm run package -- --no-dependencies
```

Либо установите упаковщик через `pnpm install --frozen-lockfile`.
В тестах можно переопределить инструменты переменными `TEST_PYTHON` и
`TEST_CPP_COMPILER`. CI устанавливает Python 3.12, а для Windows — GCC через MSYS2.
Проверяются реальные процессы, компиляция, отмена, бесконечный цикл, ошибки,
свои аргументы, async, сохранение JavaScript и формирование отчёта.
