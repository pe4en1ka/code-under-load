# Код под нагрузкой

Расширение VS Code для исследования производительности JavaScript-функций:
запускает до четырёх реализаций на данных разного объёма и показывает график
времени выполнения прямо в редакторе.

**Автор:** Мамедов Тимур Назимович, **группа М3108**.  
Лабораторная работа №3 по ИСРПО.

## Возможности

- Сравнение от одной до четырёх экспортируемых функций одного модуля.
- CommonJS (`.cjs`, `.js`) и ESM (`.mjs`, `.js` с `type: module`).
- Случайные, возрастающие и убывающие массивы чисел; пользовательский генератор аргументов.
- Синхронные функции и функции, возвращающие Promise.
- Отдельный процесс Node.js, общий тайм-аут и кнопка отмены в уведомлении.
- Прогрев, повторные измерения, медиана, минимум, максимум и P95.
- Общий график сравнения, линейная или логарифмическая шкала размера входа.
- Таблица результатов, сохранение CSV и JSON (в JSON есть все исходные замеры).
- Предзаполнение имён функций из выделения или предыдущего эксперимента.

## Требования и запуск

VS Code 1.85+ и установленный **Node.js 18+**, доступный через `node`.
Если Node.js не найден, задайте полный путь в настройке `codeUnderLoad.nodePath`.
Откройте проект в доверенном режиме VS Code.

### Запуск из исходников

1. Откройте эту папку в VS Code.
2. Нажмите **F5**, выбрав конфигурацию «Код под нагрузкой».
3. В новом окне **Extension Development Host** откройте `examples/algorithms.cjs`.
4. Вызовите команду **«Код под нагрузкой: Исследовать производительность»**
   через `Ctrl+Shift+P` или контекстное меню редактора.
5. Введите `uniqueSlow, uniqueFast`, размеры `100, 1000, 5000, 10000`,
   выберите случайный массив.
6. Дождитесь отчёта. Наведите курсор на точки, переключите шкалу,
   сохраните результаты кнопками JSON или CSV.

Для работы расширения и тестов зависимости устанавливать не нужно.

### Установка VSIX

В панели расширений VS Code выберите **… → Install from VSIX…** и укажите
`code-under-load-0.1.0.vsix`. После установки команда доступна без F5.

### Сборка установочного файла

```sh
npm install
npm run check
npm test
npm run package -- --no-dependencies
```

Для воспроизводимой установки упаковщика также можно использовать
`pnpm install --frozen-lockfile`. Единственная dev-зависимость — официальный
`@vscode/vsce`; расширение не имеет runtime-зависимостей.

## Контракт исследуемого модуля

Функции должны быть **экспортированы**, просто выделить произвольный фрагмент
или локальную функцию недостаточно. Все сравниваемые функции получают одинаковую
структуру аргументов. При встроенном генераторе это один массив чисел:

```js
function unique(values) {
  return [...new Set(values)];
}
module.exports = { unique };
```

Для нескольких аргументов или другой структуры данных экспортируйте генератор
`generateInput(size, seed)`, возвращающий **массив аргументов**, и выберите
«Свой генератор». Пример:

```js
export function generateInput(size, seed) {
  return [Array.from({ length: size }, (_, i) => i + seed), size + seed - 1];
}
export function find(values, target) {
  return values.indexOf(target);
}
```

Готовый пример сравнения поиска — `examples/custom-input.mjs`:
функции `linearSearch, binarySearch`, генератор «Свой генератор».
Для default-экспорта введите имя `default`.
Все импорты и зависимости исследуемого модуля должны разрешаться обычным Node.js.
Модуль перед измерением сохраняется на диск.

## Настройки

| Настройка | По умолчанию | Значение |
|---|---:|---|
| `codeUnderLoad.nodePath` | `node` | Исполняемый файл Node.js |
| `codeUnderLoad.repetitions` | 7 | Измерений на точку, от 3 до 50 |
| `codeUnderLoad.warmup` | 2 | Прогревочных вызовов на размер, от 0 до 10 |
| `codeUnderLoad.timeoutSeconds` | 30 | Лимит всего эксперимента, от 1 до 120 с |

Размеры — до 20 возрастающих целых чисел от 1 до 1 000 000.
Тайм-аут включает запуск Node.js, загрузку модуля, генерацию и все вызовы.

## Как интерпретировать результаты

Для каждого размера выполняется прогрев, затем несколько измерений.
Перед **каждым** вызовом создаются свежие аргументы вне измеряемого интервала;
встроенный случайный генератор использует фиксированный seed 42.
Порядок сравниваемых функций чередуется между раундами. Генератор пользователя
должен сам обеспечивать свежесть и воспроизводимость аргументов.

Измеряется вызов функции; для Promise — время до его завершения. Загрузка модуля
и генерация данных в замер не входят. Медиана уменьшает влияние одиночных выбросов.
P95 рассчитывается методом ближайшего ранга; при семи повторах совпадает с максимумом.

Это практический эксперимент, а не доказательство сложности O(n).
На результат влияют JIT, сборка мусора, нагрузка компьютера и погрешность таймера.
Очень быстрые функции дают шумные результаты. Не сравнивайте числа из разных сред
как абсолютную оценку качества алгоритма. Плагин не проверяет равенство результатов
функций: корректность алгоритмов нужно проверить отдельно.

## Ограничения

- Первая версия работает с JavaScript в Node.js, без TypeScript и браузерного DOM.
- Сравнение выполняется в одном модуле; состояние модуля сохраняется между вызовами.
- Модуль и его импорты выполняются как обычный локальный код со всеми его правами.
  Отдельный процесс защищает отзывчивость редактора, но не является песочницей.
- Отмена и тайм-аут завершают процесс измерений; процессы, запущенные самим модулем,
  не управляются плагином.
- Побочные эффекты и незавершённая асинхронная работа делают сравнение недостоверным.
- Расширение не отправляет измерения или исходный код в сеть.
